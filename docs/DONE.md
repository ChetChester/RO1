## 嚴重 Bug（會影響遊戲數值正確性）

### [x] #1 DEX 被動技能屬性膨脹
- **位置**：`js/engine.js` recomputeDerived() 第 194 行
- **問題**：`dexFlat` 被動技能直接修改 `state.stats.dex`，每次呼叫 recomputeDerived() 都會再加一次，導致 DEX 隨升級/轉職/加點無限累加
- **影響**：owleye Lv5（dexFlat=5）在 10 次 recomputeDerived 後 DEX 多出 50 點
- **觸發時機**：升級、轉職、加點、穿脫裝備、插拔卡片、死亡復活、離線結算
- **修法**：在 recomputeDerived 開頭先算出 passiveDexBonus，加入 cDex 參與衍生數值計算；computeAspd() 改用 effectiveDex；移除 dexFlat 對 state.stats.dex 的直接寫入
- **修復日期**：2026-07-26 ✅

### [x] #2 騎乘術 maxMonsters 無效
- **位置**：`js/engine.js` recomputeDerived() 的 `case 'riding'`
- **問題**：`state.maxMonsters = Math.max(state.maxMonsters || 1, 1)` 跟 1 取大值永遠等於原值，是個從來沒生效過的空動作
- **調查結果**：騎乘術**真正的效果本來就在運作**。技能敘述寫的是「生怪速度+25%」，`spawnMonster()` 看 `hasRiding` 把補怪間隔從 3000ms 降到 2250ms、清場後從 500ms 降到 375ms，這段一直是對的
- **為什麼不改成拉高同屏怪物數**：`gameTick()` 的怪物攻擊迴圈是 `state.monsters.forEach(...)`，**場上每一隻怪都會打玩家**，而玩家普攻只打 `monsters[0]`。拉高上限對單體流是純粹增加挨打量，會把一個獎勵技能變成懲罰。（若之後想給 AoE 流一個上限獎勵，那是獨立的平衡決定，不是修這個 bug）
- **順便修掉的真 bug**：`maxMonsters` 原本是「`setEncounterMode()` 直接寫值 + 被動技能 `Math.max` 疊上去」的可變狀態，只要疊過一次就再也降不回來——切到遠攻模式（該只有 1 隻）會殘留近戰的數字。現在改成在 `recomputeDerived()` 由 `encounterMode` 推導，`setEncounterMode()` 只改模式再重算
- **實測**：近戰 max=5 → 切遠攻 max=1 → 切回近戰 max=5；騎乘術學或不學都不影響 max，但 `hasRiding` 正確切換
- **修復日期**：2026-08-01 ✅

### [x] #3 角色分頁 DEF 精煉顯示錯誤
- **位置**：`js/ui.js` renderCharacterTab() 第 1282 行
- **問題**：顯示時把所有欄位精煉等級加總後傳入 getRefinementDefBonus(total)，但戰鬥計算時是逐欄位個別計算
- **影響**：顯示的 DEF 精煉加成與實際不符
- **修法**：改為逐欄位計算後加總，與 equippedDef() 保持一致
- **修復日期**：2026-07-26 ✅

### [x] #4 Wizard baseAspd 格式錯誤
- **位置**：`js/data.js` 第 279 行 / `js/engine.js` computeAspd()
- **問題**：`baseAspd: 150` 是數字而非武器類型物件，computeAspd() 取 `job.baseAspd[weaponType]` 會得到 undefined
- **影響**：巫師 ASPD 設定被忽略，回退到預設值 154
- **修法**：修正 computeAspd() 同時支援數字與物件格式——數字代表全武器統一值，物件依武器類型查表
- **修復日期**：2026-07-26 ✅

### [x] #5 doubleattack 技能類型錯誤
- **位置**：`js/data.js` 第 200 行 / `js/engine.js` playerAttack()
- **問題**：描述為「被動技能，普攻有機率造成二連擊」，但 `type: 'damage'` 被當主動技
- **影響**：自動戰鬥中會嘗試施放此技能，而非被動觸發
- **修法**：改為 `type: 'passive'` + `passiveStat: 'doubleAttack'`；新增 `doubleAttackChance` 陣列（10%~55%）；在 playerAttack() 中第一段命中後檢查是否觸發二連擊，第二段傷害 ×1.1~2.0
- **修復日期**：2026-07-26 ✅

### [x] #56 轉生系統 + 轉職只保留本系路線（2026-08-08）
- **位置**：`js/engine.js` `doRebirth()` / `rebirthBlockReason()` / `rebirthSkillPoints()` / `pruneOtherJobLines()` / `jobPrunePreview()` / `doJobChange()`；`js/ui.js` `renderRebirthPanel()` / `confirmRebirth()` / `confirmJobChange()`；`css/style.css` `.rebirth-panel`
- **條件**（使用者指定）：基礎等級 99 ＋ 職業等級 50 ＋ **1,000,000z**，**每隻角色只能轉生一次**（`REBIRTH_MAX = 1`）
- **效果**：變回新手、等級與經驗歸 1、**素質全部歸 1 並發 100 點素質點**、發 **11 點**新手技能點、扣 100 萬。裝備／道具／卡片／圖鑑／成就全部保留
- **轉生的定位是「把本職練得更強」，不是體驗別的職業**（使用者 2026-08-08 明確界定）。所以**路線鎖死**：`doRebirth()` 把轉生前走過的職業鏈存進 `state.rebirthPath`（例 `['swordsman','knight']`），之後 `canJobChange()` 只放行那條路上的下一站，走完再接 `nextLocked` 的進階二轉
  - `rebirthPathNext()` 走到原路終點時會回傳 `nextLocked[0]`（例 `lordknight`）。那六個職業還沒進 `JOB_TREE`，所以 `canJobChange()` 查不到職業就安全擋下——**等資料補進去會自動接上，不必再改這裡**
  - 沒轉生過的角色不受影響，六條線照樣自由選
  - **實測**：騎士轉生後，新手只有「劍士」可選、其餘五條全部擋下並給出理由「轉生後只能重走原本的路線，下一站是「劍士」」；劍士只有騎士可選；回到騎士時下一站是 `lordknight` 但 `canJobChange` 回 false

#### A. 那 11 點是算出來的不是寫死的
`rebirthSkillPoints()` 從資料推導：新手四個技能滿級共需 **20 點**，職業等級 1→10 自然拿到 **9 點**，所以補 **11 點**——「滿級時剛好點滿新手全部技能」。之後若動了新手技能表，這個數字自動跟著變。
**實測**：轉生後 11 點 → 練到 JOB10 共 20 點 → 四個技能全部點滿、**剩餘 0 點**。

#### B. 素質是歸零重發，不是保留再加 100
官方轉生就是重置再給 100 點轉生加成。保留 Lv99 的素質再送 100 點會直接壞掉平衡。

#### C. 轉職只保留本系路線
- **以前是反過來的**：`doJobChange()` 有一段刻意「保留所有已學技能」。那條規則在沒有轉生的年代碰不到（`next` 只往下走，一輩子只在一條線上），**加了轉生就會讓兩條線的技能同時掛在身上**
- 判斷用的是**技能 id 的集合**不是職業 id：超級新手的 `borrowSkillsFrom` 在載入時就把六個一轉的技能整份併進自己的 `skills`，照職業 id 比對會把它們誤刪。實測超級新手學了六條線各一個技能，清理後**一個都沒少**
- `jobPrunePreview()` 只回報不修改，UI 拿它列出「會刪掉哪些技能、幾點未使用技能點」讓玩家確認。**沒有東西要刪就不打擾**（正常一路往下轉不會跳確認）
- 轉生也走同一條規則
- **實測**：騎士轉生 → 預覽列出 11 個技能＋60 點未用技能點 → 轉生後只剩新手技能、`jobLevelHistory` 清空；法師學了火/冰/雷箭術後，切劍士線的預覽正確列出 4 個技能＋18 點

### [x] #57 進階二轉框架（六個職業，技能分批補）（2026-08-08）
- **位置**：`js/jobs.js` 六個 `JOB_TREE` 條目 + `JOBS_TRANS_PENDING` 瘦身；`js/engine.js` `hpSpFrom` / `computeAspd()`；`js/data.js` `aspdJobKey()` / `jobCanUseWeapon()`；`js/ui.js` `renderJobTree()` 第四層 + `confirmJobChange()`；`css/style.css` `.tree-wip`

#### A. 為什麼這一批這麼便宜
| 資產 | 狀況 |
|---|---|
| 官方技能清單 | ✅ `ro_skill_data/all_skills.json` 四層全齊，帶官方 id／中文名／maxLv |
| **攻速表** | ✅ 官方轉生二轉的攻速**跟原二轉完全相同**，靠 `aspdFrom` 指回本職，不新增表 |
| **HP/SP 表** | ✅ 官方轉生職用的也是同一張表，差別在固定加成 → 靠 `hpSpFrom` 指回本職，加成折進 `hpMod`/`spMod`，**不複製 100 格陣列** |
| 引擎鉤子 | ✅ #56 的 `rebirthPathNext()` 走到原路終點會回傳 `nextLocked[0]`，資料補進去就自動接上 |

- **`aspdJobKey()` 放在 `js/data.js`**：`jobCanUseWeapon()` 也要用，而那支在 data.js。用 `typeof JOB_TREE` 擋載入順序（jobs.js 比 data.js 早載，但這支只在執行期被呼叫）

#### B. 四個共通設定與理由
| 設定 | 值 | 理由 |
|---|---|---|
| `jobLevelMax` | 70 | 官方轉生二轉就是 70（一般二轉 50）。多出來的 20 級＝20 點技能點，剛好夠點那批新技能，不必另外發點 |
| `baseLevelReq` | 70 | **本作自訂**。官方的轉職條件是另一套階層（轉生一轉 job 40），本作沒有那一層，改用基礎等級當門檻：一轉 10 / 二轉 40 / 進階二轉 70，間距一致 |
| `hpMod`/`spMod` | 本職 ×1.25 | 官方轉生職的體質加成就是這個量級。六個一致，之後調平衡只動這個係數 |
| `bonusLevels` | 沿用本職 + 51~70 再補一輪 | 職業加成是累計繼承的，多出來的 20 級不能是白練 |
