## 嚴重 Bug（會影響遊戲數值正確性）

### [x] #1 DEX 被動技能屬性膨脹
- **位置**：`js/engine.js` recomputeDerived() 第 194 行
- **問題**：`dexFlat` 被動技能直接修改 `state.stats.dex`，每次呼叫 recomputeDerived() 都會再加一次，導致 DEX 隨升級/轉職/加點無限累加
- **影響**：owleye Lv5（dexFlat=5）在 10 次 recomputeDerived 後 DEX 多出 50 點
- **觸發時機**：升級、轉職、加點、穿脫裝備、插拔卡片、死亡復活、離線結算
- **修法**：在 recomputeDerived 開頭先算出 passiveDexBonus，加入 cDex 參與衍生數值計算；computeAspd() 改用 effectiveDex；移除 dexFlat 對 state.stats.dex 的直接寫入
- **修復日期**：2026-07-26 ✅

### [x] #2 騎乘術 maxMonsters 無效
- **位置**：`js/engine.js` recomputeDerived() 的 `case 'riding'`
- **問題**：`state.maxMonsters = Math.max(state.maxMonsters || 1, 1)` 跟 1 取大值永遠等於原值，是個從來沒生效過的空動作
- **調查結果**：騎乘術**真正的效果本來就在運作**。技能敘述寫的是「生怪速度+25%」，`spawnMonster()` 看 `hasRiding` 把補怪間隔從 3000ms 降到 2250ms、清場後從 500ms 降到 375ms，這段一直是對的
- **為什麼不改成拉高同屏怪物數**：`gameTick()` 的怪物攻擊迴圈是 `state.monsters.forEach(...)`，**場上每一隻怪都會打玩家**，而玩家普攻只打 `monsters[0]`。拉高上限對單體流是純粹增加挨打量，會把一個獎勵技能變成懲罰。（若之後想給 AoE 流一個上限獎勵，那是獨立的平衡決定，不是修這個 bug）
- **順便修掉的真 bug**：`maxMonsters` 原本是「`setEncounterMode()` 直接寫值 + 被動技能 `Math.max` 疊上去」的可變狀態，只要疊過一次就再也降不回來——切到遠攻模式（該只有 1 隻）會殘留近戰的數字。現在改成在 `recomputeDerived()` 由 `encounterMode` 推導，`setEncounterMode()` 只改模式再重算
- **實測**：近戰 max=5 → 切遠攻 max=1 → 切回近戰 max=5；騎乘術學或不學都不影響 max，但 `hasRiding` 正確切換
- **修復日期**：2026-08-01 ✅

### [x] #3 角色分頁 DEF 精煉顯示錯誤

- **修復日期**：2026-07-26 ✅

### [x] #4 Wizard baseAspd 格式錯誤
- **位置**：`js/data.js` 第 279 行 / `js/engine.js` computeAspd()

### [x] #5 doubleattack 技能類型錯誤

### [x] #11 怪物硬防/軟防被合併成一個數字（傷害公式 B 案）（2026-08-02）
- **位置**：`js/data.js` 的 `MONSTERS[*].def` / `defSoft`；`js/engine.js` `defOf()` / `mitigateDamage()`
- **問題**：`ro_monster_data/monsters_all.json` 的 `def` 欄位原本是「硬防+軟防」兩個值（例：蝎子 `"16+17"`、波利 `"2+1"`），當初匯入時**直接相加**變成單一數字（33、3）。這兩者在 RO 是不同運算：硬防是**比例減傷**、軟防是**固定扣血**，合併後丟進同一條百分比公式，不論用哪個世代的公式都是錯的
- **修法**：`tools/split_monster_def.js`（從官方原始檔重算，天生冪等）替 `MONSTERS` 補上 `defSoft`，`def` 只留硬防。`mitigateDamage(raw, 硬防, 軟防)` 改成 `原始傷害 × (4000+硬防)/(4000+10×硬防) − 軟防`
- **成果**：改寫 681 隻怪。可遇怪 431 隻裡 **415 隻有官方拆分資料**，16 隻官方原始檔沒給（維持現值當純硬防，清單在工具輸出裡）。可遇怪平均 def 133.7 → **硬防 87.4 + 軟防 46.3**
- **呼叫端統一走 `defOf(mon, scale, magic)`**，配展開運算子 `mitigateDamage(raw, ...defOf(monDef))`。`scale` 給「無視部分防禦」的持續傷害用（硬軟同比例縮）
- **魔法傷害不扣軟防**：官方魔法根本不看 DEF（看 MDEF），軟防那種固定扣血更是物理專用。本作還沒有魔防資料，所以魔法沿用硬防那半邊維持手感，但軟防歸零。**這一條不是可有可無的**——實測隕石術對邪惡向日葵（軟防 45）單跳 25 點，若跟著扣軟防會被壓到 1 點，整個場地技等於作廢
- **實測**（Lv81 騎士 / 日本刀 / ATK 353，普攻無暴擊）：波利(2+1) 351→351、蝎子(16+17) 299→292 −2%、沙漠之狼(114+45) 263→237 −10%、邪惡向日葵(158+45) 246→218 −11%。軟防越高的怪，單擊傷害越低——這正是官方行為
- **副作用**：暴擊無視 DEF（#12），所以連軟防也一起無視，暴擊流的相對價值又上升了一階
- **修復日期**：2026-08-02 ✅

### [x] #28 技能傷害改走官方傷害鏈（#12 的續篇）（2026-08-02）

### [x] #12 體型／屬性／武器浮動的套用位置與官方不同（傷害公式 C 案）（2026-08-01）
- **位置**：`js/engine.js` `weaponChainDamage()`、`recomputeDerived()` 的 ATK 分桶
- **修法**：ATK 拆成三個桶子（總和仍然是 `state.atk`，其他 20 幾處讀 `state.atk` 的地方一行都沒改）
  - `_atkWeapon` 武器本體＋精煉＋箭矢＋裝備/卡片 ATK → **吃體型、屬性、武器浮動**
  - `_atkStatus` 素質衍生 ATK × 職業係數 → 不吃
  - `_atkMastery` 熟練度被動、大聲吶喊 → 不吃（官方「熟練度無視體型懲罰」）
- **實測影響**（60 等騎士 / 日本刀 ATK130 Lv3 / 總 ATK 343，武器只佔 38%）：
  | 地圖 | 舊 | 新 | |
  |---|---|---|---|
  | 普隆德拉原野·東 | 276 | 309 | +12% |
  | 妙勒尼山脈1 | 229 | 276 | +21% |
  | 獸人地下洞窟1 | 268 | 280 | +4% |
  差異大小取決於該圖的體型／屬性組合，全小型怪的圖收益最大（體型懲罰以前是打在全部 ATK 上）
- **武器浮動**：改成以 **1.0 為中心、±武器等級×5%**（等級越高的武器擺動越大），取代原本不分來源的 0.85~1.15
- **一處刻意不照參考計算機**：計算機的浮動中心是 `1 + STR/200`。實測那一項單獨再 +11%，性質比較接近「額外的 STR 收益」而不是浮動，而且 STR 已經在素質 ATK 賺過一次，所以中心留在 1.0。要改回去就是把 `weaponChainDamage()` 的 `mid` 改成 `1 + 總STR / 200`
- **暴擊改為無視 DEF**（官方規則）：對巨石怪（DEF 236、減傷後只剩 67%）實測，暴擊從「只比普攻多 50%」變成「多 125%」。以前高 DEF 怪身上的暴擊幾乎沒有意義
- **產出估算同步改用同一條鏈**：暴擊分開算再用暴擊率加權（因為暴擊無視 DEF 也無視閃避）。實測 49 秒 DPS 誤差 3%、經驗誤差 -8%
- **範圍**：只動普通攻擊。技能傷害當時仍走舊的 `baseDmgStat × mult` 鏈 → **已於 2026-08-02 由 #28 補上**

## 刻意偏離官方的平衡設定（不是 bug，是設計決定）

### 掉落率下限（2026-08-01）
- `tools/buff_drop_rates.js`：一般掉落 `chance < 0.001` 一律拉到 **0.001（0.1%，約 1000 隻掉 1 個）**；卡片一律 **0.0005（0.05%，約 2000 隻掉 1 張）**
- **理由**：官方最稀有的那批低到 0.01%（約 1 萬隻），放置遊戲節奏下等於永遠拿不到；同時卡片刻意壓在一般掉落的一半，維持「稀有寶物」定位
- 影響：一般掉落 981 項、卡片 832 項；其餘 10,187 項維持官方值
- **後續計畫**：整體內容完善後，會加「難度模式」搭配整體掉寶率倍率，屆時這組下限可能改成由難度係數推導

### BOSS 只在 MVP 模式出現（2026-08-01）
- `tools/bosses_to_mvp_only.js`：`isBoss:true` 的怪全部從 `MAPS[*].monsters` 移除（214 項 / 108 張圖），併進 `MVP_MAP_DATA`（101 → 168 張圖）
- `spawnMonster()` 不需修改——既有邏輯就是「MVP 模式開 → 20% 從 `MVP_MAP_DATA` 挑，否則走地圖權重表」
- 效果：關閉 MVP 模式時完全不會遇到 BOSS
